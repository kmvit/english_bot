# Telegram-бот «Учитель английского»

Личный бот для одного пользователя: ведёт разговор на английском (текст и голос),
исправляет грамматику и лексику, разбирает произношение по фонемам, помнит
прогресс ученика. Реализация [SPEC.md](SPEC.md).

## Как это работает

**Текстовое сообщение:** профиль + топ-5 повторяющихся ошибок + последние 20
реплик → LLM → JSON → форматированный ответ → запись в БД.

**Голосовое сообщение:**

1. Скачивание `.ogg/opus` → `ffmpeg` → `wav 16 kHz mono PCM`.
2. Распознавание — один из двух бэкендов (`SPEECH_BACKEND`):
   - **whisper** (по умолчанию): faster-whisper локально, бесплатно, только текст;
   - **azure**: непрерывное распознавание с Pronunciation Assessment
     (unscripted, granularity=Phoneme, prosody включён) — транскрипт и оценки
     произношения приходят одним вызовом.
3. Сжатие отчёта Azure: транскрипт, 5 общих баллов, 3–5 худших слов с ошибочными
   фонемами. Полный отчёт в LLM не уходит — это десятки килобайт. У Whisper
   оценок нет, и блок произношения в ответе просто не появляется.
4. LLM: системный промпт учителя + профиль + история + транскрипт с оценкой.
5. Ответ: текст (разговорная часть → исправления → произношение) и голосовое с
   озвучкой **только разговорной части**.
6. Запись в БД: сообщение, ответ, найденные ошибки, баллы произношения, расходы.

## Стек

- Python 3.12, aiogram 3, asyncio
- LLM: **OpenAI SDK через OpenRouter** (`LLM_MODEL`, резервная `LLM_FALLBACK_MODEL`)
- STT: **faster-whisper** локально, либо Azure AI Speech с оценкой произношения
- TTS: **Kokoro** или **Piper** локально (нейронные голоса, без ключей), либо
  Azure Neural TTS — выбирается через `TTS_BACKEND`
- SQLite через aiosqlite
- Docker + docker-compose, один контейнер

## Запуск

Локально (нужен установленный `ffmpeg`):

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
cp .env.example .env   # заполнить токены
.venv/bin/python -m bot
```

В Docker:

```bash
docker compose up -d --build
```

## Деплой на сервер

Боевой сервер — Ubuntu с systemd, без Docker: так же развёрнуты соседние
сервисы на той же машине, и лишний демон там не нужен.

Первичная установка (от root, сервер чистый):

```bash
git clone https://github.com/kmvit/english_bot.git /opt/english_bot
cp /opt/english_bot/.env.example /opt/english_bot/.env   # заполнить
/opt/english_bot/deploy/install.sh
```

Скрипт ставит `ffmpeg` и `libgomp1`, собирает venv, **заранее скачивает модели**
(иначе первое голосовое ждало бы загрузку), ставит юнит systemd и запускает бота.

Обновление после изменений в коде:

```bash
/opt/english_bot/deploy/deploy.sh
```

### Если Telegram и OpenRouter недоступны с сервера

С российского хостинга `api.telegram.org` не отвечает, а `openrouter.ai`
отдаёт 403. Трафик заворачивается в SSH-туннель до зарубежной машины:

```bash
cp /opt/english_bot/deploy/english-bot-tunnel.env.example /etc/default/english-bot-tunnel
chmod 600 /etc/default/english-bot-tunnel   # заполнить хост, пользователя, ключ
```

затем в `.env` бота указать локальный конец туннеля:

```
PROXY_URL=socks5://127.0.0.1:1080
```

`install.sh` сам поставит юнит туннеля, если найдёт `/etc/default/english-bot-tunnel`,
и бот будет ждать его запуска. Туннель поднимается через `ssh -N -D` с
`ExitOnForwardFailure` — без этого флага ssh остался бы жив при занятом порте,
systemd счёл бы туннель поднятым, а бот стучался бы в пустоту. `ServerAliveInterval`
роняет ssh при обрыве, после чего systemd перезапускает его через 10 секунд.

Проверить, что туннель работает:

```bash
curl -x socks5h://127.0.0.1:1080 -s -o /dev/null -w "%{http_code}\n" https://api.telegram.org
```

HuggingFace с сервера доступен напрямую, поэтому модели качаются без туннеля.

### Резервные копии

`deploy/backup.sh` снимает копию базы через API sqlite (не `cp`: бот пишет в
любой момент, и копирование файла может поймать базу на середине транзакции),
жмёт gzip и держит последние 14. Таймер systemd ставится вместе с сервисом и
срабатывает в 04:30. В Docker-развёртывании таймер ставится на хосте — база
лежит в томе и доступна ему напрямую:

```bash
cp /opt/english_bot/deploy/english-bot-backup.{service,timer} /etc/systemd/system/
systemctl enable --now english-bot-backup.timer
```

Журнал: `journalctl -u english-bot -f`. В юните стоит `MemoryMax=2G` — при
утечке ядро убьёт бота, а не соседние сервисы.

**Важно:** Telegram допускает только один экземпляр с одним токеном. Перед
запуском на сервере остановите локальную копию, иначе оба получат
`TelegramConflictError` и сообщения не дойдут ни до одного.

## Перевод ответов

Реплика бота приходит сразу с русским переводом под ней. Перевод просится тем же
запросом, что и сама реплика (поле `reply_ru`), а не отдельным вызовом: иначе
каждый ход стоил бы вдвое. Кнопка «Перевести» при включённом переводе прячется —
нажимать её незачем.

Переводится только разговорная часть. Строки разбора остаются английскими: их
ученик должен видеть как есть.

Отключается в `/settings` — бывает полезно, когда перевод под рукой мешает
вчитываться в английский.

## Подсказка развернуть ответ

Когда ответ ученика короче `SHORT_ANSWER_WORDS` (по умолчанию 4 слова), ход
помечается для модели, и та решает, стоило ли отвечать подробнее. Если вопрос
звал к рассказу — под репликой появляется строка с наводящим вопросом. Если
короткий ответ был уместен («Do you like coffee?» → «Yes, I do»), подсказки нет.

Разделение намеренное: длину считает код — это дёшево и детерминированно, а
уместность видна только из вопроса, на который отвечали, и это дело модели.

Баллов за ответы бот не ставит. Оценки языковой модели не откалиброваны: один и
тот же ответ получит сегодня 7, завтра 5, — а цифра создаёт видимость точности,
которой нет. Подсказка говорит, что делать, и этим полезнее балла.

## Манера учителя

Переключается в `/settings` по кругу:

| Манера | Как говорит |
|---|---|
| `neutral` | ровно и доброжелательно — как раньше |
| `casual` | как приятель в баре: сокращения, обрывки фраз, мат к месту |
| `savage` | то же плюс разнос за ошибки |

В жёсткой манере бот опирается на журнал повторяющихся ошибок: у каждой есть
счётчик, и «мы это проходили пять раз» — не фигура речи, а факт из профиля.

Две вещи заданы в промпте жёстко и не зависят от манеры. Ругань всегда про
ошибку, никогда про человека: студент, которого унижают, перестаёт разговаривать,
а на этом практика и заканчивается. И сами исправления остаются такими же
точными — манера меняет тон, а не требования.

Это отдельная настройка от `TEACH_PROFANITY`: та управляет отношением к мату
**ученика**, эта — речью **бота**.

## Крепкие выражения

`TEACH_PROFANITY=true` снимает самоцензуру: бот не вымарывает мат, не заменяет
его звёздочками и не пересказывает фразу в обход. Само по себе крепкое слово
перестаёт считаться ошибкой — исправляется грамматика рядом с ним
(«he fucking girl» → «he's fucking a girl in every city»), а про уместность бот
говорит одной строкой, без нравоучений.

Выключено по умолчанию: это осознанный выбор ученика, а не поведение из коробки.

## Что бот делает сам

- **Утренний вопрос** в выбранное время: пишет первым, опираясь на последние
  разговоры. Выключен по умолчанию, включается в `/settings`. Бот, который только
  отвечает, забывается за неделю — это главное средство против этого.
- **Недельная сводка** по воскресеньям: сообщения, новые слова, темп речи и
  ошибки, которые держатся крепче всего. Если за неделю занятий не было, сводка
  не приходит — пустой отчёт только раздражает.
- **Переоценка уровня** раз в `LEVEL_CHECK_EVERY` сообщений.

## Тренировка ошибок

`/drill` берёт до трёх ошибок, которым пришёл срок, просит модель составить по
предложению на каждую и проверяет ответы. Интервалы растут с серией верных
ответов — 1, 2, 4, 9, 21 день; ошибся — серия обнуляется и повтор назначается на
завтра. Так редкая ошибка не отнимает время, а стойкая возвращается, пока не
закрепится.

Во время тренировки текст считается ответом на задание, а не репликой диалога.

## Кнопки

- **Нижняя клавиатура** — «🎯 Тренировка», «📌 Ошибки», «📖 Словарь»,
  «📈 Прогресс», «💬 Тема», «⚙️ Настройки»; появляется после `/start`
  и восстанавливается командой `/help`.
- **«Тема»** предлагает варианты из интересов ученика, добитые общими до шести.
- **Экран `/settings`** — инлайн-меню: уровень, интересы, время утреннего вопроса,
  голос вкл/выкл и режим «только голос». Правка не требует повторного онбординга.
- **Под каждым ответом учителя** — «🇷🇺 Перевести» и «💡 Подробнее». Перевод сохраняет
  английские фразы в строках ❌/✅, пояснение идёт по-русски на A1-A2 и по-английски с B1.
  Каждое нажатие — отдельный запрос к модели, он учитывается в `/cost`.

Профиль бота (имя, описание, меню команд) настраивается через Bot API; список команд бот
ставит сам при каждом запуске.

## Тесты

```bash
.venv/bin/python -m pytest
```

Юнит-тесты: сжатие отчёта Azure, разбор JSON от модели, подсчёт стоимости,
форматирование, БД. Интеграционные:

- LLM-слой на моке клиента: фолбэк на резервную модель при 429/5xx/таймауте,
  понижение `response_format`, ответ прозой вместо JSON, отказ модели;
- ход диалога целиком: реальная SQLite, моки LLM и Azure;
- обработчики через реальный `Dispatcher` с поддельной сессией Telegram:
  контроль доступа, онбординг, команды, кнопки настроек, действия под ответом,
  голосовой пайплайн, деградация при падении внешних API;
- конвертация `ffmpeg` на настоящих файлах (пропускается, если ffmpeg нет).

## Устойчивость и стоимость

- Доступ только `ALLOWED_USER_ID`, остальным — отказ.
- Голосовые длиннее `MAX_VOICE_SECONDS` (60 с) отклоняются до обращения к Azure.
- Ошибки Azure и LLM не роняют бота: пользователь получает понятное сообщение,
  подробности уходят в лог. Необработанные исключения ловит `dispatcher.errors`.
- Резервная модель включается при 429, 5xx, таймауте и обрыве соединения.
- В контекст уходит не более `HISTORY_LIMIT` (20) последних реплик.
- Стабильная часть системного промпта идёт первым сообщением, изменяемый профиль
  вторым — так работает автоматическое кеширование префикса у OpenAI. Попадания
  в кеш видны в `/cost` (кешированные токены учитываются по своему тарифу);
  кеш включается только если префикс достаточно длинный (~1024 токена).
- Каждый запрос пишется в `usage_log`: токены и стоимость LLM, секунды аудио
  Azure, символы озвучки. `/cost` показывает сумму за месяц. Если OpenRouter
  вернул фактическую стоимость в `usage.cost`, берётся она, иначе — расчёт по
  тарифам `PRICE_*` из `.env`.
- Уровень ученика переоценивается раз в `LEVEL_CHECK_EVERY` (50) сообщений
  фоновой задачей — ученик не ждёт лишний запрос.

## Требования к серверу

Замеры на Apple M5, на ядре VPS ждите в 2–2.5 раза медленнее:

| | Память | Минута речи |
|---|---|---|
| Whisper `small` (int8) | 900 МБ на пике | 8.9 с на 2 потоках |
| Piper (голос medium) | 220 МБ | 0.9 с на 6 с речи |

Whisper почти не ускоряется дальше двух ядер: 4 потока дают всего 17% против
двух. Платить за 4+ ядра под эту задачу бессмысленно — берите 2 ядра и 4 ГБ.
В `docker-compose.yml` стоит `mem_limit: 2g`, чтобы бот не утянул память
у соседей по серверу при сбое.

Модели (Whisper ~250 МБ, голос Piper ~63 МБ) скачиваются при первом запуске
в том `./data` и переживают пересоздание контейнера.

## Выбор бэкенда распознавания

| | Whisper (`small`, локально) | Azure Pronunciation Assessment |
|---|---|---|
| Стоимость | $0 | F0 бесплатно до 5 ч/мес, дальше ~$1/час |
| Оценка произношения | нет | баллы по словам и фонемам, беглость, интонация |
| Скорость (минута речи) | ~8 с на CPU | ~длительность записи |
| Память | ~1 ГБ | не нужна |

Замер на Apple M5: `small` распознаёт минуту речи за 7.8 с и **сохраняет ошибки
ученика дословно** — в том числе «He don't like coffee but he drink tea», что
критично для бота-корректора. Модель `base` быстрее втрое, но на живой записи
переврала две фразы из пяти и выдумала ошибку, которой не было, — использовать
её для проверки грамматики нельзя.

Переключение — одна строка в `.env`, код обоих бэкендов лежит в `bot/speech/`.

### Беглость речи

Whisper отдаёт тайминги слов — из них считаются темп речи, число и доля пауз.
Это единственное, что можно измерить в устной речи без облачной оценки
произношения, и этого хватает, чтобы `/progress` показывал динамику до
подключения Azure. Паузой считается разрыв длиннее 0.4 с: всё короче — обычные
промежутки между слогами.

### Озвучка

`TTS_BACKEND=auto` берёт Azure, если заданы его ключи, иначе Piper. Piper
работает офлайн и бесплатно; голос задаётся в `PIPER_VOICE` (по умолчанию
`en_US-lessac-medium`) и скачивается автоматически с HuggingFace при первом
ответе. Список голосов — в репозитории `rhasspy/piper-voices`.

Голосов два движка:

| | Piper | Kokoro |
|---|---|---|
| Модель | 60 МБ на голос | 310 МБ + 27 МБ на все голоса |
| Синтез 8 с речи | ~1 с | ~1.7 с |
| Частота | 22 кГц | 24 кГц |
| Интонация | ровная, дикторская | живее, с паузами и акцентами |

`TTS_LENGTH_SCALE` задаёт темп одинаково для обоих: 1.0 — как записан голос,
больше — медленнее. У Kokoro параметр скорости устроен наоборот (больше единицы
значит быстрее), поэтому внутри он пересчитывается — чтобы одно и то же число
означало одно и то же на любом движке.

Замедление портит интонацию: фонемы растягиваются равномерно, и естественный
ритм сплющивается. Поэтому большие значения лучше не брать — 1.15 звучит заметно
живее, чем 1.3, при почти той же разборчивости.

## Отличия от SPEC.md

- **LLM:** вместо Anthropic SDK и `claude-sonnet-5` — OpenAI SDK через
  OpenRouter (по решению владельца проекта). Отсюда же: вместо явного
  `cache_control` на системном блоке — автоматическое кеширование префикса,
  поэтому стабильная инструкция вынесена в отдельное первое системное сообщение.
- **Распознавание:** по умолчанию локальный Whisper вместо Azure — до проверки
  аккаунта Azure. Блок произношения при этом не формируется, `/progress` об этом
  сообщает. Код Azure сохранён и включается через `SPEECH_BACKEND=azure`.
- **Озвучка:** Piper вместо Azure Neural TTS, по той же причине. Проверено, что
  SpeechKit от Яндекса для распознавания речи ученика не подходит: на живой
  записи он вставил лишнее слово и потерял апостроф, то есть подменил ошибку
  ученика своей. Для синтеза он пригоден, но Piper не требует ключей и сети.
- Модель по умолчанию `openai/gpt-4.1`, резервная `openai/gpt-4.1-mini` — меняются
  через `LLM_MODEL` / `LLM_FALLBACK_MODEL` без правки кода. Тарифы `PRICE_*` в
  `.env` тоже выставлены под gpt-4.1 (нужны лишь как запасной расчёт, если
  OpenRouter не вернул `usage.cost`).
