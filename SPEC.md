# Telegram-бот «Учитель английского»

## Цель
Личный бот для одного пользователя. Ведёт разговор на английском (текст и голос), исправляет грамматику, лексику и произношение, помнит прогресс ученика.

## Стек
- Python 3.12, aiogram 3.x, asyncio
- LLM: Anthropic SDK, модель `claude-sonnet-5` (Haiku 4.5 как дешёвый fallback через env)
- STT + оценка произношения: Azure AI Speech SDK (`azure-cognitiveservices-speech`), Pronunciation Assessment в режиме unscripted (без эталонного текста), granularity=Phoneme, включить prosody
- TTS: Azure Neural TTS (`en-US-JennyNeural` по умолчанию, голос в env)
- ffmpeg: конвертация Telegram `.ogg/opus` → `wav 16kHz mono PCM`; ответный `.mp3` → `.ogg/opus` для отправки как voice
- БД: SQLite через aiosqlite (профиль ученика, история, ошибки)
- Конфиг через `.env`: `TELEGRAM_TOKEN`, `ANTHROPIC_API_KEY`, `AZURE_SPEECH_KEY`, `AZURE_SPEECH_REGION`, `ALLOWED_USER_ID`, `CLAUDE_MODEL`, `TTS_VOICE`
- Docker + docker-compose, один контейнер

## Пайплайн голосового сообщения
1. Скачать voice → ffmpeg → wav.
2. Azure: одним вызовом получить транскрипт и pronunciation assessment (accuracy, fluency, prosody, completeness; по каждому слову — score и ошибочные фонемы).
3. Сжать результат в компактный JSON: transcript, общие баллы, 3–5 худших слов с фонемами (не отправлять весь отчёт в LLM — экономия токенов).
4. Claude: system prompt учителя + профиль ученика + последние N реплик + текущий транскрипт с JSON оценки.
5. Ответ пользователю: текст (структура ниже) + голосовое с озвучкой только разговорной части ответа.
6. Записать в БД сообщение, ответ, найденные ошибки (грамматика/лексика/произношение).

Текстовое сообщение проходит шаги 4–6 без Azure.

## Системный промпт (суть, доработать при реализации)
- Ты дружелюбный учитель английского, разговариваешь только по-английски; объяснения ошибок — коротко, по-русски, если уровень ученика ниже B1 (уровень из профиля).
- Всегда сначала продолжай беседу (1–3 предложения, задай встречный вопрос), затем блок исправлений.
- Исправляй только реальные ошибки, не переписывай стиль. Формат: ❌ как сказал → ✅ как надо + одна строка почему.
- Если есть данные о произношении: назови не больше 2 худших слов, укажи фонему, дай совет по артикуляции и пример слова с тем же звуком. Игнорируй баллы выше 80.
- Подстраивай сложность лексики под уровень ученика. Отвечай в JSON: `{"reply": "...", "corrections": [...], "pronunciation": [...], "new_errors": [...]}` — бот сам форматирует сообщение.

## Профиль ученика (таблица `profile`)
level (A1–C1, обновляется раз в ~50 сообщений по запросу к Claude), interests, native_language=ru, recurring_errors (список: тип, описание, счётчик, последняя дата). Топ-5 повторяющихся ошибок подмешивается в промпт.

## Команды
- `/start` — короткое приветствие, спросить уровень и интересы
- `/topic <тема>` — начать разговор на тему
- `/mistakes` — мои частые ошибки с примерами
- `/progress` — динамика баллов произношения за 7/30 дней
- `/voice on|off` — присылать ли голосовые ответы
- `/reset` — очистить историю диалога (профиль остаётся)

## Ограничения и требования
- Доступ только `ALLOWED_USER_ID`, остальным — отказ.
- Голосовые длиннее 60 с — попросить короче (Azure real-time ограничение и стоимость).
- Prompt caching для system prompt (cache_control на системном блоке).
- В контекст передавать не более 20 последних реплик.
- Логировать стоимость: токены Claude и секунды аудио Azure по каждому запросу, `/cost` для суммы за месяц.
- Ошибки Azure/Claude не должны ронять бота — отвечать понятным сообщением и логировать.
- Тесты: юнит-тесты на сжатие отчёта Azure и на парсинг JSON от Claude; интеграционные — моки внешних API.

## Порядок разработки
1. Каркас aiogram + текстовый режим с Claude.
2. Профиль и БД, команды.
3. Голос: ffmpeg + Azure STT + assessment, передача в Claude.
4. TTS-ответ.
5. `/progress`, `/cost`, Docker.
